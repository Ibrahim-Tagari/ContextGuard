Context Guard

Prototype build — v0.3.0

What gets blocked

Category Examples Action
Hate speech Direct slurs, dehumanizing comparisons, explicit incitement Blocked (blurred, one-click reveal)
Islamophobic content Conspiracy narratives ("Great Replacement"), sweeping generalizations, delegitimizing claims about Islam Blocked (blurred, one-click reveal)

Both categories are blocked by default. You can turn either off from the popup if you'd rather it left alone entirely.

Manual block/unblock

You're always the final word on any individual post: right-click it → Block this content or Unblock this content. That choice is saved and reapplied automatically if the extension sees the same text again — including reversing something it auto-blocked incorrectly.

Where this runs

The content script runs on every site you visit (not just named social platforms) so it can catch comment sections on any site, not only the handful with hand-tuned support. On unfamiliar sites it falls back to a generic heuristic scan rather than a site-specific one, so accuracy will vary more there than on the sites it's been tuned for.

Known limitations

  • Detection is regex/pattern-based, not a trained classifier — it will miss coded language and can misfire on quotes, news reporting, or counter-speech, despite the context guards in place.
  • The wordlist is a small starter set. It needs to be built out from a vetted hate-speech lexicon, with review from affected communities, before this should be trusted beyond testing.
  • The generic (non-hand-tuned) scanner is a rough heuristic and will both miss real posts and occasionally grab the wrong chunk of a page on unfamiliar site layouts.

Data & privacy

All detection runs locally in your browser. No page content is sent anywhere. Settings, counts, and your manual block/unblock choices are stored only in your browser's local extension storage.

See the project README for architecture details and how to extend the wordlist or add a classifier for ambiguous cases.
